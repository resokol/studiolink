# Обновление клиентских страниц

Каждый выпуск получает уникальный BUILD_ID. Та же версия встраивается в клиент.
Для установки одного выпуска на нескольких серверах используется общий
`STUDIOLINK_RELEASE`; локальная установка и VPS показывают одинаковую версию.
`GET /api/version` возвращает идентификатор реально запущенной сборки из её
каталога, с `Cache-Control: no-store` и `CDN-Cache-Control: no-store`.
HTML страниц также формируется без кеширования; хешированные JS/CSS можно
по-прежнему кешировать.

Внизу интерфейса отображаются адрес сервера, версия и кнопка проверки.
Проверка выполняется при открытии страницы, возвращении к вкладке и раз
в минуту, пока вкладка видна. При отличии версии появляется уведомление.
Перезагрузка происходит только после нажатия «Обновить приложение»:
автоматически прерывать эфир нельзя. Ссылка сохраняет комнату и остальные
параметры, добавляя `_update=<новая версия>` для обновления HTML.
Сетевые ошибки не вызывают перезагрузку. На страницах monitor/output
уведомлений и фоновой проверки нет, чтобы сохранить чистый выход.

Проверка сравнивает страницу с её сервером. Она не копирует сборки между
локальным сервером и VPS. Поэтому обе серверные установки нужно обновлять;
адрес и версия позволяют сразу отличить разные установки.

Старые страницы, открытые до внедрения механизма, нужно один раз обновить
вручную после установки новой сборки на соответствующий сервер.

## Проверки

- `node apps/web/tests/app-update.cjs`: версии, откат, проверка ответа,
  сохранение комнаты и параметров при обновлении.
- `node apps/web/tests/app-update-notice.cjs`: обнаружение обновления без
  автоматической перезагрузки, нажатие кнопки, недоступная сеть, чистые выходы.
- `TEST_BUILD_DIR=.next-updater-20260926 node apps/web/tests/app-update-api.cjs`:
  совпадение BUILD_ID, API и клиентской версии, заголовки кеширования,
  отсутствие уведомления на выходах. По умолчанию тестируется localhost:3001.

Локальная сборка: `.next-updater-20260926`. Предыдущая: `.next-quality-20260926`.

## Установка на VPS и откат

- Образ: `studiolink_web:updater-20260926-03690141`.
- Контейнер: `studiolink-web`.
- Исходники и Dockerfile выпуска:
  `/opt/studiolink/releases/updater-20260926-03690141`.
- Основной compose ссылается на этот каталог и образ. Пароли и данные
  остаются в прежних `web.env`, `/opt/studiolink/data` и `data/runtime`.
- Предыдущий контейнер остановлен и сохранён:
  `studiolink-web-before-updater-20260926-03690141`.
- Предыдущий compose:
  `/opt/studiolink/backups/updater-20260926-03690141/docker-compose.yml`.

Для отката остановить текущий веб-контейнер, переименовать его в свободное
резервное имя, вернуть предыдущему имя `studiolink-web` и запустить его.
Также восстановить предыдущий compose из резервной копии. Данные общие
для обеих версий. Временный тестовый контейнер удалён после проверки.
